What's different

Ticket-to-agent runners exist. Owlshift makes three bets of its own.

01

The question loop is the product

Questions can come at any stage, and they are asked on the ticket. The answer is checked before anything resumes, and there is no limit on rounds.

02

Scheduling is enforced

Blockers gate dispatch. Declared resources keep two tickets in flight from colliding, whether an agent or a person holds them.

03

A ticket is a pipeline, not a session

A plan before code, review by a fresh run, on another model when the configuration names one, the project's gate run confined, and the cost measured for each ticket.

It stays yours

Your tracker

Linear, GitHub Issues or Markdown files in your repository. Questions, answers and delivery reports live on the ticket: no new board.

Your agents

Claude Code, with Codex if you want it, on your own subscription. Owlshift never asks for a model API key.

Your machine

One light native background service. Agent runs are confined, and secrets are kept in the system keychain.

Your merge

No agent merges. Owlshift opens the pull request and repairs it; merging stays a person's unless the project opts in.

What it is not

  • Not an IDE, a chat or a new board.
  • Not an auto-merger by default.
  • Not a hosted service.

Install

Install the latest release, on macOS, on Linux, or on Windows through WSL2.

macOS

brew tap pitchopp/owlshift https://github.com/pitchopp/owlshift
brew trust --formula pitchopp/owlshift/owlshift
brew install owlshift

Linux, and Windows through WSL2

curl -fsSL https://raw.githubusercontent.com/pitchopp/owlshift/main/install.sh | sh

Then owlshift doctor checks the machine: git, Claude Code, and whether agent runs can be confined.
