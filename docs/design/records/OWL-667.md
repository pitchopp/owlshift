# OWL-667 · Make the daemon and child-step tests stop timing out under load

Settles: [build plan](../build-plan.md), "The test bench", "Waits in tests" (a wait through several steps; deadlines a test hands to the code) and "First starts in tests" (the holding harness).

## The failures (2026-11-26 and 2026-11-27)

Nine owlshift-testkit tests failed in a full workspace nextest run and passed alone. That was OWL-655's gate of 2026-11-26 18:23 UTC (2630 tests in 1610 s, 6 failed) and its rebase run's own run of 2026-11-27 01:30 UTC (2658 tests in 5283 s, 8 failed):

- child_steps: `a_sigterm_during_two_builds_checks_both_and_both_resume`, `a_build_canceled_in_watch_s_own_process_stops_and_parks_the_watch_going_on`, `two_projects_two_in_flight_each_share_two_slots`;
- daemon: `s11_a_checked_stop_resumes_both_builds_and_a_kill_quarantines`, `a_canceled_build_is_stopped_checked_and_parked_then_resumed_from_its_checkpoint`, `an_upgrade_drain_lets_the_steps_under_way_finish_then_exits_75`, `a_watch_that_cannot_serve_pauses_its_project_until_one_serves`;
- executor: `a_run_cut_at_its_deadline_leaves_nothing_running`, `setup::a_build_that_broke_its_setup_repairs_it`.

On 2026-11-27, at a load average of 59 to 84 (median 67, other agents' builds and gates sharing the machine), the same full run passed all 2693 tests in 750 s.

## Causes

Each failure is a fixed time bound on a path whose length the test does not check.

- **A wait of `wait::REACHED` (120 s) across a whole run of steps.** "Both Builds under way" waits from the watch's start through each intake and dispatch to each Build's start. The failing gate's log against a run at load 65 (seconds):

  | Step | Failing gate | Load 65 |
  | --- | --- | --- |
  | watch start to DEMO-1's intake decided | 15 | 1.1 |
  | DEMO-1's intake run | 15.2 | 1.5 |
  | DEMO-1's INTAKE to DEMO-2's intake decided | 35 | 4 |

  Each step took about ten times longer. The whole run of them takes about 20 s at load 65, so it crosses 120 s once the machine is about six times slower. Five tests: the two child_steps waits (`child_steps.rs` "both Builds under way", "the Build under way") and three daemon ones (`daemon.rs:315`, `Bench::wait_for`).
- **`SlotBound`'s `WEDGED` (300 s), counted from the drain's start.** It bounded the whole drain, not one holder. `two_projects…` failed it in both threads, at 328 and 340 s.
- **Deadlines handed to the executor that the passing path had to beat.** `a_run_cut…` cut its run at 3 s, before the helper had written its pid file (`executor.rs:637`, "file not found"). `a_build_that_broke_its_setup_repairs_it` gave the gate 3 s, so the setup 1 s, which the repaired setup had to beat.
- **The daemon bench's 1 s pass.** The daemon lifts a paused project's pause once a watch tried again still runs a pass after its start (`crates/owlshift-runner/src/daemon/supervise.rs`, the lift in the supervision loop). That pass is 60 s in production and 1 s on the bench. A stand-in that cannot serve, and takes more than a pass to start and end, is lifted, then paused again: "Paused" is said again and the operator notified again. With the stand-in made to wait 1.5 s before it ends, `a_watch_that_cannot_serve…` failed at `daemon.rs:616` in 8 s, as in the failing run (6.8 s), with "Paused acme/web" said three times and "served again" twice. The daemon's rule is kept; no product code changes.

## As built

- `wait::through(steps, what, context, done)`: `wait::REACHED` for each step the test waits through, one after the other, as `crates/owlshift-cli/tests/cli.rs` already bounded its driver's four waits at `REACHED * 5`. A step is a start or end of the daemon, of the watch, or of a ticket's step (an intake, a Build's start, resume, end or checked stop), or a watch pass awaited. The daemon bench's `Bench::wait_through` and `Bench::ended_through` use it; `wait_for` and `ended` are one step.

  | Test | Wait | Steps |
  | --- | --- | --- |
  | child_steps `a_sigterm…` | both Builds under way | 5: watch start, 2 intakes, 2 Build starts |
  | | watch to end after SIGTERM | 3: 2 Builds checked, watch end |
  | | the resume drain (`SlotBound`) | 5: watch start, 2 Build resumes, 2 Build ends |
  | child_steps `a_build_canceled_in_watch…` | the Build under way | 3: watch start, intake, Build start |
  | child_steps `two_watches…` (`SlotBound`) | both intakes run | 4: 2 watch starts, 2 intakes |
  | child_steps `two_projects…` (`SlotBound`) | four Builds ask | 10: per project, watch start, 2 intakes, 2 Builds |
  | daemon `s11…` | both Builds under way | 6: daemon start, watch start, 2 intakes, 2 Build starts |
  | | the daemon's end after SIGTERM | 4: 2 Builds checked, watch end, daemon end |
  | | both Builds resumed | 4: daemon start, watch start, 2 Build resumes |
  | | the quarantine, notified | 2: daemon start, watch start |
  | | three more passes | 3 |
  | daemon `a_canceled_build…` | both Builds under way | 6, as `s11` |
  | | three more passes | 3 |
  | | DEMO-1's Build resumed | 2: the pass that dispatches it, its Build start |
  | | the daemon's end after SIGTERM | 4, as `s11` |
  | daemon `an_upgrade_drain_lets…` | both Builds under way | 6, as `s11` |
  | | the daemon's end after the drain | 4: 2 Build ends, watch end, daemon end |

- `SlotBound` (child_steps): a wedge is the same live holders on the machine's slots for `WEDGED` (300 s), counted from the last change of those holders, only while one stands. A drain is also bounded at `REACHED` for each step it runs on the machine (new argument), so steps started one after another forever still fail. The resume drain of `a_sigterm…` is now a `SlotBound` (200 passes counted while no Build holds a slot) instead of 200 passes in all.
- `a_run_cut…`: every pid the helper wrote is checked gone at each run, and a run whose helper had not written both pid files when cut runs again on a new bench with twice the deadline, `REACHED` at most. A process left behind fails at once and is never retried.
- `setup::a_build_that_broke_its_setup_repairs_it` and `setup::a_setup_failure_a_build_cannot_repair_fails_the_run`: a case whose subject is not the deadline runs under the bench's 60 s gate deadline. A case that is cut, or held past the deadline, runs under a 30 s gate (a 10 s setup) with a stand-in that outlasts it: `sleep OUTLASTS`, and perl's child `sleep 30`.
- daemon: `Bench.timing`, `TIMING` by default. The two paused-project tests run on `PAUSE_TIMING`, a pass of 5 s. `a_killed_watch_starts_again…` times each restart from before its signal.
- `step_child::holding_harness` is written through `stand_in::write` and started once with no argument, which its new first line ends at once. Its first start, the scan's, no longer falls inside the waits above.
- Cost of a passing run, these three binaries alone at a load of about 65: the two paused-project tests went from 4 s to 20 s each, and the two setup tests from 9 s to 19 s each.
- Cost of a real defect: a wait whose state never comes now fails after up to 12 minutes (6 steps) instead of 2. A live slot holder that never ends still fails `two_projects…` after 5 minutes. Steps started one after another forever fail it at its ceiling, 20 minutes (10 steps).

## Rejected

- Raising `wait::REACHED` for every wait: a wait for one state would fail five times later for nothing, and it reaches none of the other three causes.
- A cap on nextest's threads: measured 2.5 times slower under load ([OWL-666](OWL-666.md)).
- Waits whose bound restarts while something moves: a watch passing idly moves, so a watch that never dispatches would still need a cap. That is the per-step bound, with more code.
- Separating the daemon's lift delay from its retry pace in `Timing`: product code and a design change, for a bench setting.

## Left as they are

- `three_tickets_build_at_once_and_a_do_typed_meanwhile_waits`'s 200 passes, not counted on the slots' holders by OWL-425's decision.
- The bounds of `tests/on_demand.rs` and of the other test binaries.
- In production, a real watch tried again on a paused project that runs past the 60 s pass before it finds it cannot serve has its pause lifted, then paused again and notified again.
- daemon `a_sigterm_and_a_hard_kill_leave_no_ui`, which failed once under five runs of main at once, cause not found.
