# OWL-642 · Keep two runners from filing two repairs for one break when they file within seconds of each other

Settles: [architecture](../architecture.md) section 5, "The repair ticket", "Not twice", and section 7's table. It closes the first accepted residual of [OWL-640's record](OWL-640.md) (two filings within about 8 seconds, and a failed search that files anyway) and, under `policy.claims = "remote"`, the first of [OWL-622's](OWL-622.md) (a crash between the tracker's answer and `base.json`'s write).

## As built (2026-11-23)

- *A failed search.* `repair_for` (`on_demand/base_hold.rs`) read a `Tracker::proposed` error as "nothing found" and filed. It now leaves the hold untried (`NotKept::Unread`) with a `repair_unfiled` warning that says the search failed and will be tried at the hold's next step. This is a change of behaviour on every tracker and claims mode: a search that keeps failing, such as GitHub's six lists on a rate limit or Markdown's on a ticket file it cannot read, now files no repair until it answers.
- *The contract.* `RepairClaim` (`owlshift-contracts/src/refs.rs`, format 1, schema `repair-claim`) holds `runner`, `operator`, `claimed_at`, `ticket` (absent while filing) and `repairs`. `repair_claim_ref(key)` is `refs/owlshift/repairs/<key>`. The key, `base::repair_key`, is the step and the same 12 hexadecimal digits of the command's SHA-256 as the marker.
- *The git side.* `claims::repair` (`owlshift-runner/src/claims/repair.rs`) has `read`, `push_claim` and `give_back`. `read` is one `ls-remote`, then a fetch to `refs/remotes/owlshift/repairs/<key>`, which the isolation check leaves out and which no claims listing reads. `push_claim` creates the ref or replaces a commit, leased. `give_back` deletes the ref or puts the commit back, leased on the runner's own. They share the ticket claims' push, floor check and fetch: `make_commit` and `fetch_claim` were split into `commit_file` and `fetch_file`, with the ticket claims' error texts unchanged.
- *The decision.* `owlshift_core::base::claim_move` is pure. A claim naming an open repair is taken again. One naming none is waited on for `REPAIR_CLAIM_LEASE_MS`, 15 minutes, either side of the reader's clock. Anything else is replaced: the break's count is the larger of `base.json`'s break and the claim's `repairs`, unless `Checks::passed_after` finds a pass of the head after the claim was taken, and the bound `MAX_BREAK_REPAIRS` holds on that count. A named ticket is open as `Checks::reusable` reads it: a state the tracker cannot say leaves it open, and the read of its text then decides, an outage ending as `Unread`, never as a filing.
- *The filing.* `break_claim` and `take_break_claim` run under the project's lock, as the tracker calls do. The claim is taken naming none and counting the repair to come; the tracker files only once that push lands. A take `origin` refuses is read again: a claim there is a filing elsewhere (`NotKept::Elsewhere`, the `repair_claimed` decision event, the hold untried); none is `Unread`. `name_repair` names the ticket once the lock is let go, a failure there being a `repair_problem` warning. A filing the tracker refuses calls `give_back`.
- *Docs.* The `policy.claims` comment of `owlshift init`'s template says a broken base's repair is claimed there too; `docs/reference/configuration.md` was regenerated from it.
- *Tests.* Core: `a_repair_claim_is_taken_again_waited_on_or_replaced_within_the_bound`. Contracts: the repair claim's round trip in `event_claim_and_state_rejections`. Claims against a bare remote: `a_repair_claim_is_created_once_and_moved_only_from_the_commit_read`, which covers a second create refused, a stale lease refused, a give-back and a later format. Bench (`repair_scenarios.rs`): `two_runners_holding_one_break_within_the_lag_file_one_repair`, two seats whose search cannot see a Markdown repair, as GitHub's cannot for 6 to 8 s, leaving one repair and one claim naming it; `a_colleagues_claim_naming_no_repair_holds_the_filing_until_its_lease_ends`; `a_failed_search_or_claim_files_nothing_until_both_answer`. OWL-622's main scenario asserts that under `local` origin holds no repair claim.

## Premise

The guarantee rests on the git server applying a ref's create and update as compare-and-swap. Live check C3 ([build plan](../build-plan.md), "C3 — passed") ran 8 concurrent creates and takeovers on GitHub under `refs/owlshift/check-c3/`, with exactly one winner per round, and T1 (2026-11-19, "P10 · Teams") ran leased updates and deletes under `refs/owlshift/claims/`. The repair claims are the same `refs/owlshift/` family, pushed by the same adapter code, so no new live check was run.

## Built otherwise than designed

- *A claim naming none, this runner's.* The alignment let this runner re-file under its own unnamed claim. The panel found that a restart within the tracker's lag would then file twice, so the runner's own unnamed claim is waited on for the lease, as another runner's is.
- *A refused filing gives the claim back.* Not in the alignment; added in review so that a transient refusal does not hold every runner of the team for the lease.
- *The count in the claim.* Added in review: without it, each runner's two repairs made a break's bound two per runner.

## Accepted residuals

- Under `claims = "local"`, the default for a project of one machine, two runners of a team can still file twice within the lag: nothing is pushed there.
- A claim whose naming push fails after the filing names none; once its lease ends, a runner on another commit, whose search cannot match this one's marker, files a second repair.
- Repair claims are never deleted, one per failing command; `git push origin --delete refs/owlshift/repairs/<key>` removes one.
- A runner that recorded no pass since a claim counts that claim's break, so a later break on the same command files one repair fewer, or none and is told; an unnamed claim taken over counts the repair it was filing, even if it was never filed.
- A filing slower than the 15-minute lease lets a colleague take its claim over and file a second.
- While a claim names none, each held step records a `repair_claimed` decision.
