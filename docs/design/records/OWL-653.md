# OWL-653 · Re-admit a yielded ticket past its own pull request so its refresh rebase runs

Settles: [architecture](../architecture.md) section 5, "A stopped holder yields", *The resume*; "Tolerated overlap", *The refresh*; "The collision rule", *Who goes on* ("A ticket with an open pull request never waits"). The design does not change: the resume admits a yielded ticket "its pull request open or not ... by a first admission's rules", and nothing there makes the ticket's own pull request a holder.

## As built (2026-11-26)

**The case.** On Locary on 2026-11-26, LOC-2200 (pull request #1783) yielded its ten paths at 08:23 UTC after six hours waiting for its decider; other tickets took some of them. Its decider answered at 08:35, the ticket went back to In Review, and watch decided a refresh rebase (`cause=overlap`), a sibling's merge having changed a path both shared. From 08:35 to at least 10:20, six repair steps stopped before their run: "LOC-2200 waits: pull request #1783 holds zone `.claude/rules/ci-and-tests.md`, which it held before it yielded: it is admitted again once pull request #1783 no longer holds it". #1783 was LOC-2200's own pull request, green and mergeable: it could only close by merging, and it could only merge after that refresh. `owlshift why LOC-2200` said `now: not waiting`.

**The cause.** `OnDemand::locked_load` gave `Outside::holders` the other tickets' refs and the ticket itself with no ref, `(&p.ticket, None)`. `holders` records a pull request as Owlshift's own only from a ref that holds and names it, so the ticket's own open pull request was read as another pull request, an outside holder. Under `rebase`, `collision::weigh` tolerates no outside holder, and `admit_yielded` weighs the ticket as a first admission is (`Dispatched::Now`, not delivered). The ticket's own pull request, listing the files the ticket changed, collided with the zones its yielded record held. Watch's own read passes the ticket's real ref, so only the on-demand admission met the wait.

**The fix.** `locked_load` gives the ticket's own ref when it holds (`held::holds`: at Watch while its pull request is followed, or at any stage past Ready). Its delivered pull request then joins the ticket in `Holders::own`, which `Holders::join` adds only to the entries of `in_flight`; the ticket has no entry there, so those files are dropped and its own pull request holds nothing against it. A ref that does not hold keeps the old `None` path: the ticket is still Owlshift's, so its tracker ticket is never read as a person's. Real holders still make it wait as a first admission would. `delivery_hold` keeps `(&p.ticket, None)`: it checks a first delivery, which has no pull request of its own.

**Shown by `why`.** `weigh_admission` emitted the `watch` = `waits` decision event only when a command steps for watch. The commands watch runs at Watch (a repair, a correction, the person steps, a review loop) prepare through `prepare_at_watch`, which did not step, so a held-back re-admission recorded nothing and `why` said "not waiting". `Prepared` gets `for_watch`, set by `prepare_at_watch`; `weigh_admission` emits the event when `stepping || for_watch`. It is a flag of its own rather than `stepping`, which also makes a command stop at the next change of stage and decides other paths of the run. Watch retries a stopped step every `RETRY_AFTER` (10 minutes), so a watch-run admission tells its wait only when the ticket's current wait, as `why` folds the events, is not that one already (`told_already`): `why`'s history gets one line per distinct wait, not one per retry. The event keeps its shape, so `why` names the holder with its existing phrase: `now: pull request #7 holds zone `AGENTS.md`, which it would touch`.

**Under `exclusive`.** The self-wait cannot happen. `admit_yielded`'s `exclusive` branch clears the yield and returns before `weigh_admission`, reading no outside holder. The check that remains, `admit_stage`, weighs the ticket as delivered while its pull request is followed (`held::of(..., delivery_followed, ...)`), and `collision::weigh` gives a delivered ticket nothing to wait for: its `before` is empty. `admit_build` returns early in a review loop, and since this fix every admission that goes through `locked_load`, a Build's included, leaves out the ticket's own pull request under either switch.

**Tests.** In `crates/owlshift-testkit/tests/on_demand/overlap_scenarios.rs`:

- `a_yielded_delivered_ticket_is_refreshed_past_its_own_pull_request_and_merges_on_green`: under `overlap = "rebase"` and `merge = "all"`, DEMO-1 delivered and yielded, a sibling's merge on `AGENTS.md`; the refresh rebase runs once (`cause` = `overlap`), a `yield` = `readmitted` event is told, and the pull request merges on green.
- `a_yielded_ticket_held_back_at_its_readmission_is_shown_waiting_by_why`: the same, with a person's pull request #7 on `AGENTS.md`; two passes stop with the wait, one event is told, `why DEMO-1` shows it now, and once #7 is closed the refresh runs.

The fake GitHub gets `own_files`, the files its own open pull request lists, empty unless a scenario sets them. The bench's Build holds the whole repository, which cannot yield (`TicketHeld::yieldable`), so both scenarios first give DEMO-1 a record admitted on `AGENTS.md`, then yield it.

**Checked on the old code (2026-11-26).** With `locked_load` given `None` again, the first scenario fails: watch's passes stop with "DEMO-1 waits: pull request #1 holds zone `AGENTS.md`, which it held before it yielded: it is admitted again once pull request #1 no longer holds it", the Locary message, and the refresh never runs. With `|| p.for_watch` removed, the second fails on `why`, which prints "no wait recorded for it". With the dedupe removed, it fails on the count: two identical wait events in two passes.
