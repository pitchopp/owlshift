# OWL-658 · Word the other credential and secret pauses so a user fixes them without the source

Settles: [OWL-650's record](OWL-650.md), "Other pauses on credentials and secrets"; [architecture](../architecture.md) section 5, "Pause".

## As built (2026-11-26)

**The mechanism.** OWL-650's `Refusal::in_checkout` now words every lasting refusal of a credential or a secret that a person mends. `refusal::Need` carries what mends it: `GitHubSignIn` (OWL-650), `GitHubToken`, `Keychain`, `LinearKey` and `LinearApp(tracker::AppFault)`. The constructors are `Refusal::no_github_token`, `keychain`, `no_linear_key` and `linear_app`, all lasting. Once a command knows its folder, the notice becomes the message, and the technical words, which name the keychain entry, become its `detail`, printed on the line before. The daemon keeps the last line as the pause reason, so status, the UI, the digest, doctor's `service pause` line and the notification show the notice. The served watch adds the sentence "Owlshift picks the project up again within a minute." (`refusal::PICKED_UP_AGAIN`). `do`, `continue` and a typed `watch` drop it.

`do_cmd::run_with` passes `Secrets::read`'s refusal through `in_checkout` as well as the opener's. Every error of `Secrets::read` is `Refusal::keychain`: the keychain does not open, or an entry of the tracker set or the forge does not read. `owlshift release` words its refusals the same way, without the daemon's sentence, and keeps only the notice, as it printed only the message before.

**The texts, each checked against the code.**

1. No GitHub token (`forge::no_token_notice`): `cd '<checkout>'` then `owlshift init`. Without `--github-token`, `github_sign_in::step` signs in through the GitHub App with a code to enter on github.com. `init` keeps an existing owlshift.toml, and `store_secrets` keeps each secret already stored.
2. The keychain unreadable (`secrets::keychain_notice`): unlock the system keychain and let Owlshift read it (the login keychain on macOS, the Secret Service on Linux, which must be running); nothing needs storing again. No command and no folder, since `owlshift init` would store nothing new. The served watch's last sentence reads "Owlshift tries again by itself and picks the project up again within a minute." The words are `secrets::UNLOCK_KEYCHAIN`, which doctor's `KEYCHAIN_FIX` now is.
3. No Linear API key (`tracker::linear_key_notice`): `cd '<checkout>'` then `owlshift init`, pasting a personal API key made in Linear's settings under Security & access, the words of `init`'s own question. `init` asks for a secret it does not find and keeps the others.
4. The Linear app (`tracker::AppFault::notice`), by fault and by set:
   - Half of the pair stored, the project's own set: `owlshift init`, which asks for the pair when it is not whole (`store_app_credentials`). It needs no `--replace-secrets`.
   - A whole pair of its own that Linear refused (`Unauthorized`): `owlshift init --replace-secrets`, which keeps a whole pair otherwise. The notice says that it asks again for each stored key, where Enter keeps it, and signs in to GitHub again (`github_sign_in::step` skips the kept token under `--replace`). `Unauthorized` also comes from the API key, which `writing_as_app` checks the app against, so the head names "the app … or the API key it checks the app with" and the command asks for a new key if Linear revoked it.
   - The app does not see the team (`NotFound`, `writing_as_app`): make the team a public team in Linear; nothing needs storing again.
   - Each choice of the project's own set also offers to write through the API key: delete the two entries, named with their service. The notice says what that keeps and costs. The refused case adds "if the API key still works".
   - A shared set (from before OWL-308): `owlshift init`, which asks for this project's own key, where Enter keeps the shared one, then its own app. It never says to delete the shared entries. `tracker::SHARED_FIX` and `AppError::Incomplete`'s technical words now name plain `owlshift init` as well, instead of `--replace-secrets`.

A Linear app that did not answer, or answered an error a retry may clear, is still not worded: it is not a pause.

**Doctor.** `Kind::doctor` takes the folder the pause names (`doctor::init_folder`: the registered checkout when the service serves the project, otherwise the project file's folder). The `secrets` line's no-token fix, the `tracker states` line's no-key fix (`tracker::linear_key_step`) and the `tracker identity` line's steps (`AppFault::steps`) give the notice's fix in that folder. Each line keeps its technical detail. A step's folder is shown as is, not shell-quoted, as OWL-650's `sign_in_step` shows it. The `service pause` line keeps its generic step for these reasons, since the reason itself now holds the fix. Only the GitHub sign-in, matched by its exact text, has a step of its own.

**Tests.** `refusal::tests::each_need_is_said_with_its_notice_once`; `forge::tests::no_token_stored_is_said_as_a_sign_in_from_its_folder`; `secrets::tests::the_keychain_notice_says_to_unlock_it_and_nothing_else`; `tracker::tests::no_linear_key_is_said_with_the_command_and_its_folder`, `each_app_fault_is_said_with_its_fixes`, `an_app_that_could_not_be_used_is_refused_by_what_mends_it` and `deleting_the_app_is_never_advised_for_shared_entries`; `do_cmd::refusals::each_credential_refusal_ends_with_its_notice`; `doctor::tests::the_credential_lines_give_the_pauses_fix_in_its_folder` and `the_linear_app_is_checked_as_do_checks_it`.

**Left open.**

- No end-to-end scenario on the CLI bench: OWL-650's `cli_sign_in_scenarios` already covers the path from a refusal to the last line and the pause, and the bench keychain cannot be made to fail to open.
- `Secrets::read`'s mapping is tested through `Refusal::keychain`, not through a keychain that fails: no test can build a `KeychainError` outside the platform crate.
- `secrets::shared_notice` and doctor's warning about a shared set still name `--replace-secrets`. They are not pauses, and the flag still works there.
