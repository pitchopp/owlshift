# OWL-627 · Detect pdm, Maven, Composer and .NET in owlshift init

Settles: [runtime and operations](../runtime-and-operations.md), "Stack detection (P9)", "More stacks (OWL-624, OWL-627)"; [architecture](../architecture.md) section 8, "Caches a run may write". The second slice of [OWL-624](OWL-624.md), whose method it keeps.

## As built (2026-11-22)

- **Detection.** Three sources join `owlshift_core::stack::detect`, after Gradle and before the Makefile: `maven`, `composer`, `dotnet`, each reading file names only, so `MANIFESTS` and `init::read_root_files`, which lists every root name, did not change. pdm joins uv and poetry in `PYTHON_MANAGERS`, which one function, `locked_manager`, turns into lines; the note pdm had is gone, and a `pdm.lock` now wins over a `requirements.txt` as poetry's does.
- **pdm** (`pyproject.toml` and `pdm.lock`): setup `pdm install`, `pdm run` before each tool, `run_caches.PDM_CACHE_DIR = "pdm"` and `PDM_LOG_DIR = "pdm-log"`, and a note to ignore `.pdm-python`.
- **Maven** (`pom.xml`): gate `mvn -B -Dmaven.repo.local="$MAVEN_USER_HOME/repository" verify`, `run_caches.MAVEN_USER_HOME = "maven"`, and a gate note that the line reads the variable, to set by hand. Maven 3.10.1's launcher reads no variable that moves the home or the repository (`MAVEN_ARGS` and `MAVEN_OPTS` only), so the property is in the line. Designed with `./mvnw` when the wrapper is there: the wrapper fails confined on macOS (R1), so the line is `mvn` with it too, and a note says the wrapper is not run, that Maven must be installed, and that it runs instead of the version the wrapper pins.
- **Composer** (`composer.json`): with `composer.lock`, setup `composer install --no-interaction` and no run cache, a note naming `COMPOSER_CACHE_DIR`; with a `phpunit.xml`, `phpunit.dist.xml` or `phpunit.xml.dist`, gate `vendor/bin/phpunit`. Without the lock or the settings, a note each, as for a `Gemfile`.
- **.NET** (the one `*.sln` or `*.slnx` at the root, or with none the one `*.csproj`, `*.fsproj` or `*.vbproj`, single-quoted for the shell when its name needs it): setup `DOTNET_SYSTEM_NET_SECURITY_USENETWORKFRAMEWORK=1 dotnet restore -m:1 -nodeReuse:false <file>`, gate the same with `dotnet test`, `run_caches.DOTNET_CLI_HOME = "dotnet"`, and a note giving the reasons. Designed as plain `dotnet restore` and `dotnet test` with `NUGET_PACKAGES` and `DOTNET_CLI_HOME`: R1 found the plain lines fail confined on macOS and `NUGET_PACKAGES` not needed. A `global.json` adds a note that the switch needs .NET 10 or later. Several solutions, several projects and no solution, or a `global.json` alone give a note with the lines.
- **Held by** `stack::tests::a_poetry_or_pdm_root_installs_its_lock_and_runs_through_it`, `a_maven_build_runs_verify_with_its_repository_in_a_run_cache`, `a_composer_root_installs_its_lock_and_runs_phpunit`, `a_dotnet_root_restores_and_tests_its_one_solution_or_project`, `every_run_cache_detected_passes_the_names_check`, and `init::tests::a_maven_composer_and_dotnet_root_is_written_and_loads`, which loads the Maven line, quotes and `$` included, back from the file.

## Live check R1, macOS (2026-11-22)

Script: [`owl-627.sh`](../live-checks/owl-627.sh), OWL-624's harness: per ecosystem, a fixture repository served on a local bare remote, `owlshift init --tracker markdown --skip-secrets` of this branch, its `owlshift.toml` committed unedited, then `owlshift gate`; then once per `run_caches` line, that line alone removed, and for Maven once with the property alone removed. `STACK_EDIT` applies a `sed` expression to the written file, for the experiments below, which say so.

macOS 26.6.2, Apple silicon, `sandbox-exec`. Installed for the check with Homebrew, being absent: maven 3.10.1 (openjdk 27.0.1.1 being there), pdm 2.29.7, composer 2.11.2 with php 8.6.0 and its 16 missing formulae, dotnet 11.0.100. Python 3.15.2 from Homebrew first on `PATH`.

The network of the check ran at 5 to 65 kB/s, slower while several checks shared it, against 30 minutes for a gate and a third of it for its setup. The first Maven gate was stopped at the gate's deadline with 11 MB downloaded, the first Composer setup at its deadline with 944 kB, and the first .NET restores at theirs; each was run again with `CACHE_SEED` holding what the confined run before it had written into its run caches, as OWL-624 did. Nothing was served on the loopback: every package came from its public registry. The fixtures' lock files and the Maven wrapper were made unconfined, their caches in the scratch folder.

It decides: pdm, Maven, Composer and .NET are kept, each with the lines above; every variable written passed with it set and failed with it alone removed. `COMPOSER_HOME`, `COMPOSER_CACHE_DIR` and `NUGET_PACKAGES` passed with themselves removed and are not written. The wrapper `mvnw` is not run.

## Live check R2, Linux: not run (2026-11-22)

Script: [`owl-627-linux.sh`](../live-checks/owl-627-linux.sh): the same runs in Docker, Ubuntu 24.04, bwrap, with a Linux build of this branch and the four tool chains (Maven and OpenJDK 21, PHP and Composer from the distribution, pdm from PyPI, the .NET SDK 10 from Microsoft's install script). Written and never run, so untested itself: the rig downloads several hundred megabytes, hours at this machine's rate. The variables rest on the macOS checks alone, which the rule allows; on Linux the private home lets an install with a variable left out succeed into a folder lost with the command, so the removed-variable runs are expected green there, as OWL-617 found. Left to OWL-632.

## Not checked

- Linux, above: there `mvnw` would find its temporary folder through `TMPDIR`, and .NET uses OpenSSL, so neither the wrapper's failure nor the Network.framework switch was seen there.
- A .NET SDK earlier than 10, which does not know the switch: on macOS its restore would fail on TLS as above; a note says so when `global.json` pins the SDK.
- `-m:1` and `-nodeReuse:false` separately: they were checked together, after the plain lines stalled.
- Composer's `composer test` script, and a PHPUnit whose settings name another folder than `vendor/`.
- Two confined runs writing one of the new folders at once.
