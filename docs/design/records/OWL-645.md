# OWL-645 · Make the two executor::gate timing tests pass under a single-process cargo test

Settles: [build plan](../build-plan.md), "OWL-241 — CI time", the bullet "The tests run under cargo-nextest", its recheck of 2026-11-12 (OWL-550). That recheck found that "the step stop one test asks (`process::stop_step`, in `cancel.rs`'s watcher test) stops the trees the others start", and that a lock a test releases stays held by a child another test forked. This record says what changed since. The build plan's text and `CONTRIBUTING.md`, which names nextest as the local gate, are not edited.

## The cause (2026-11-23)

The gate tests were not slow, and their deadlines were not too tight: they were killed.

- `cancel::tests::a_watcher_stops_the_step_once_the_file_appears` and `a_watcher_stops_the_step_once_its_claim_is_lost` start a real `cancel::Watcher`, which asks the step's stop, `owlshift_platform::process::stop_step`. That stop is the whole process's: it sends SIGKILL to every live tree spawned `AtCheckedStop::Stopped`, and to every one spawned until `end_step_stop` (`process/signals.rs`, `stop_step`, `register`).
- Every gate and setup command is such a tree (`executor/watch.rs`, `spawn`, through `ProcessTree::spawn_in`).
- Under `cargo test` the tests of a binary share one process. A gate command that lives until its deadline (`helper_sleep` for 1 s, `sleep 20` for 1 or 3 s) is still running when a watcher test finds its file, about half a second in. It ends by the signal, so `a_command_past_the_deadline_is_stopped` reads `"ended by a signal"` where it expects `"stopped at the gate's deadline, 1 s"`, and `a_real_command_failure_says_whose_it_is` and `setup::the_setup_has_a_third_of_the_deadline_and_the_gate_its_whole` do the same for the setup's deadline. Under nextest each test is a process of its own, which is why CI stayed green.

Reproduced on macOS 26.6.2 (Apple silicon, 18 cores, load average about 47, other agents building on the same machine), from `main` at `021c92d0`:

- `cargo test -p owlshift-runner --lib --locked -- cancel::tests::a_watcher_stops executor::gate::tests::a_command_past executor::gate::tests::a_real_command` failed both gate tests in 3 runs of 3, each with `left: "ended by a signal"`. The gate module alone passed, 34 of 34.
- The whole runner library, one run, failed the same two tests. An instrumented run (a log line in `Watcher`'s drop, not kept) showed that the two cancel tests are the only watchers in that binary.

## As built (2026-11-23)

- The two cancel watcher tests run alone in a fresh copy of the test binary, with `alone::run_alone` (OWL-414), as `slots.rs` and `quarantine.rs` do for a held lock. Their bodies moved unchanged into `#[ignore]` helpers, `helper_a_watcher_stops_the_step_once_the_file_appears` and `helper_a_watcher_stops_the_step_once_its_claim_is_lost`. They still assert the real `process::step_stop_asked()` and its end at the watcher's drop. The step's stop is now that copy's alone.
- The gate tests are unchanged. `alone.rs`'s module comment names the new case: a test that asks the process-wide step stop runs alone.
- Two flakes of the kind the OWL-550 recheck named showed in the Linux runs below, and are fixed the same way. Both come from a descriptor that a child, forked by another test of the same binary, holds until it starts its own program.
  - `daemon::instance::tests::one_daemon_holds_the_data_directory_until_it_ends` read the daemon's lock held after the daemon let it go (2 runs of 3). It and `a_daemon_adopts_only_the_lock_it_was_handed`, which reads the lock free after the same release, now run alone too.
  - `owlshift-testkit`'s `stand_in::start_once` was refused with `ETXTBSY` ("Text file busy") on a stand-in just written: Linux refuses to run a file another process still holds open for writing. This hit `first_clone`'s `a_git_older_than_the_floor_is_refused_before_the_checkout_is_touched` in 1 run of 3. The first start is now tried again while it is refused so, 10 s at most. Once a start went through, no such descriptor is left.

**No test is skipped in effect.** The helpers run on every path that runs the tests, through their wrappers, which are ordinary tests:

- CI's `cargo nextest run` (no `--run-ignored`), `owlshift.toml`'s gate and plain `cargo test` all run the wrapper. The wrapper starts the helper by its exact name.
- `run_alone` fails unless the copy exits 0 and printed `running 1 test`, so a helper that is renamed, filtered out or failing fails its wrapper. Checked on 2026-11-23: with one assertion of the lost-claim helper changed on purpose, the wrapper failed and carried the helper's panic. The change was then undone.
- Windows runs the cancel wrappers as well: `stop_step` only records the stop there. The daemon's adoption test is Unix-only, as it was.

**Other process-wide stops.**

- The platform library has one more test that asks the step's stop in its own process, `process::tests::a_step_stop_stops_the_runs_alone_until_it_ends`. It is left as it is: no other test of that binary spawns a tree `AtCheckedStop::Stopped` in the shared process. The trees of `stop_by_degrees_owning_trees` are spawned in the helper's own process, so the stop reaches only the test's own trees.
- No runner test calls `stop_by_degrees` or `stop_trees_on_signal`.

## Live check R1, Linux (2026-11-23)

**The rig.**

- Ubuntu 24.04.5 aarch64 in Docker 29.4.0 (kernel 6.12.76-linuxkit, 18 cores, 23 GB) on the same Mac, which other agents loaded throughout (load average 14 to 150).
- Rust 1.98.1. The source is copied into a volume, with the target and the registry in volumes of their own.
- Each run is one `cargo test --workspace --locked`, started with `setsid --wait` under `docker run --init`.

**What the image lacked.** Three gaps in the image failed tests in the first run on `main`, none of them this ticket's:

- **No time zone database.** `owlshift-adapters`' `harness::codex::tests` failed with "no time zone database configured". The host's `zoneinfo` is mounted read-only.
- **No `python3`.** `owlshift-cli`'s `the_notices_hold_the_crates_and_the_fonts_or_nothing` failed with `notices.sh: python3: not found`. The image gets `python3`.
- **pid 1 in the test's session.** The platform's `a_stopped_group_is_hung_up_then_continued_when_its_parent_ends` and `a_hard_kill_with_the_sentinel_stopped_still_stops_the_live_trees` failed in the full run, and again run alone, with and without `--init`. Their own comment says why: a subreaper of the same session adopts the orphan, so its group is not orphaned. Under `setsid`, as from a terminal, they pass.

**Before, on `main` at `021c92d0`.** `--no-fail-fast`, 914 s: 74 binaries passed and 3 failed, the image's two above and the runner's library. The runner's library failed the three gate tests, each with `"ended by a signal"`.

**With the change.**

| Run | Change | Result |
| --- | --- | --- |
| 1-3 | gate fix | Plain `cargo test`, which stops at the first failing binary. The gate and cancel tests passed in all three. Runs 1 and 3 stopped at the runner's library on the daemon lock test, run 2 at `first_clone` on `ETXTBSY`. |
| 4 | gate fix and the two flake fixes | `--no-fail-fast`, 1164 s: 77 binaries, 2593 tests passed, none failed, 100 ignored. |
| 5 | the same | `--no-fail-fast`, 516 s: 74 binaries passed and 3 failed, 2589 tests passed, 4 failed (below). A sixth run was stopped. |

The three gate tests and the two cancel tests passed in all five runs with the change.

**Not met: three full runs in a row.** Run 5 failed tests of the same two kinds, in tests this ticket does not touch:

- **A file just written, refused as busy (`ETXTBSY`).**
  - `owlshift-platform`'s `process::tests::own_program_spawns_the_binary_this_process_started_from` copies `/bin/sh` and runs it.
  - `owlshift-testkit`'s `daemon.rs`, `a_replaced_binary_not_newer_failing_or_stopped_leaves_the_daemon_as_it_was` and `a_session_daemon_moves_onto_a_newer_binary_with_no_gap`, at `start`'s spawn of a binary `install_binary` just copied.
- **A lock just released, read held.** The runner's `project::tests::a_commands_ticket_lock_names_its_holder_until_it_ends`.

Both kinds predate this change. They can hit any test that writes an executable and runs it, or that releases a lock and reads it free, while other tests of its binary spawn processes. Some 25 places in the tests give a file an executable mode outside `stand_in::write`, and others copy one. Fixing them one run at a time did not converge here: each run turned up new ones. They are left to a ticket of their own. Until it lands, a plain `cargo test --workspace` on Linux can still fail on them. nextest, the documented local gate, runs each test in a process of its own, where the other tests' children are not.
