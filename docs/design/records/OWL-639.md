# OWL-639 · File a second repair when a merged repair leaves the base still broken

Settles: [architecture](../architecture.md) section 5, "A broken base", "Told", "The repair ticket", "A repair that does not fix it", and "Leaving a broken commit", "The head's check"; [runtime and operations](../runtime-and-operations.md), "Notifications". Corrects the accepted residual of [OWL-622's record](OWL-622.md) that a merged repair whose head still fails opens no hold.

## Decided (2026-11-23)

The maintainer chose, at the ticket's alignment: a failing head after a repair's merge is held and files the next repair, automatically (rather than a notice alone, sending the merged repair back, or checking the repair against a fresh base before its merge); at most two repair tickets a break, a fixed constant, not a project-file key; and the head's check for every held branch, not only one with commits of its own. Two more rules came from the review of the plan: a break is told once, and a ticket that watch moves off a held commit checks the head before its Build.

## As built (2026-11-23)

- *The break* (`owlshift_core::base::Break`, `Checks::breaks`). One per failing step and command: whether it was told, whether it was told spent, and the repair tickets filed or taken again, in order (`keep_break_repair`, `break_repairs`, `break_spent`, `claim_break_told`, `claim_spent_told`). `record_check` clears every break when a check passes whose commit is the head it fetched. Kept apart from the entries on purpose: `trim` drops the oldest hold once 16 stand, and a hold that reopens on its commit replaces the entry's repair, either of which would reset a count read from the entries. At most 16 breaks, the oldest dropped.
- *`base.json` format 3* (`ProjectBase::breaks`, `KeptBreak`). Format 2 reads with no break, and one naming a break is refused; format 1 reads as before.
- *The head's check* (`owlshift_core::base::leave`, `OnDemand::leave_held`). `leave` takes the held commit's failing command and whether the head holds: a head with no verdict is checked whatever the branch, and one whose kept verdict fails at that command with no hold on it is checked again, which matches the kept verdict (`GateOnce::reuse`, `after_failure`) and holds it; only `OwnCommits` rebases onto a passing head. `leave_held` runs `run_check` with the held commit's failing command as `initiating`, follows a hold already standing on the head (`follow_hold`), and warns `base_not_followed` when the head's check fails at another command. The `base_not_rebased` warning for an uncommitted worktree no longer ends the step.
- *A ticket moved off a held commit* (`OnDemand::moved_off_hold`). Watch's step into Build fast-forwards a branch with no commits of its own (OWL-274), which makes its wait invalid; read before it is dropped, a wait of the same round, at Build, whose commit is held and is an ancestor of the new one gives its failing command to `settle` at the new commit, so that commit is checked before the Build starts. Its pass ends the break, which a fast-forwarded Build that passed its gate never recorded.
- *Filing* (`OnDemand::file_repair`, `repair_for`, `Filing`). An open repair of the command is taken again, then one found by title or marker, as before; then, with the break's two filed, none: `Repair::Unfiled`, a `repair_unfiled` warning whose reason names them (`base::repairs_spent`). A new one's description names the repairs before it (`repair_description`'s `before`). The repair kept joins its break, and the `repair` decision event carries its `attempt`. `Filing::Outlived` refiles a hold on the fetched head whose repair shows completed, found by `follow_hold`, which also takes over `settle`'s retry of a hold never told or never tried, so a hold opened at a head that no ticket is configured at is retried too.
- *Telling* (`OnDemand::tell_hold`). `file_repair` now runs before it everywhere. The hold's told mark is taken as before, and the line is shown only for the break's first hold, or for a hold that finds the break spent, once, with `repairs_spent`'s sentence added.
- *Tests.* Core: `a_held_branch_with_commits_of_its_own_leaves_for_a_head_that_passes` (every branch kind), `a_break_files_two_repairs_then_none_until_the_head_passes`. Contracts: `a_break_survives_its_file_and_format_2_reads_without_one`. Runner: `a_repairs_text_quotes_the_output_and_is_admitted_unchanged` (the second repair's paragraph, the spent sentence). Bench (`repair_scenarios.rs`): `a_repair_merged_on_a_base_still_broken_files_one_more_then_waits_for_a_person` (a done Build with commits of its own; the merge checked before the tracker shows the repair done, the repair taken again with nothing told; the next step at that head files DEMO-3 naming DEMO-2; DEMO-3's merge held with no third repair, the warning, one more notice; no run and no failed run while held; then a fix rebased and delivered) and `a_continued_ticket_with_no_commits_of_its_own_checks_the_head_and_holds_it` (a person's `continue` of a ticket with no commits of its own checks and holds the head; its repair, found unread, is kept by the next `continue` through `follow_hold`). `child_steps.rs`'s `a_base_wait_keeps_its_comment_while_another_step_runs` now rewords the gate's command on `main`'s first move: a head failing the same command would hold DEMO-2's Build, the long step the test needs beside DEMO-1's wait.

## Built otherwise than designed

- *Told once a break* revises OWL-418's "once per hold" for every hold of a break, a ticket's own failure at a newer head included, not only the holds the head's check opens: the rule reads the break, not how the hold opened.

## Accepted residuals

- A break fixed while no held ticket is left to check the head records no pass and keeps counting toward the next break on that command, which files one repair fewer, or none and is told at once.
- A repair that rewords the failing command leaves the head unmatched (`whose` compares the text): `base_not_followed`, and the head is held only once a Build there fails it.
- A held ticket whose pull request is open, or whose worktree has uncommitted paths, now makes the held commit's re-check and the head's check at each head move, one gate run each, shared by every held ticket at that head.
- More than 16 standing holds drop the oldest, which reopens at its next failure; the break's count is unaffected.
- An Owlshift older than this one reads a format-3 `base.json` as an error, which holds nothing (`base_unchecked`) until it is upgraded.
