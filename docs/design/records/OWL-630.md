# OWL-630 · Detect manifests one folder down in owlshift init (monorepos)

Settles: [architecture](../architecture.md) section 8, "Caches a run may write", "Several projects in one repository"; [runtime and operations](../runtime-and-operations.md), "Stack detection (P9)" and "More stacks". A follow-up of [OWL-624](OWL-624.md), whose method it keeps; it adds no run-cache variable.

## As built (2026-11-24)

- **Reading.** `init::read_root_files` reads the root as before, then each folder below it that `stack::reads_folder` allows (not hidden, not `node_modules`, `vendor`, `target`, `dist` or `build`, no control character in its name), a link never followed (`symlink_metadata`), and each such folder of `stack::CONTAINERS`, `apps` and `services`: the names and the manifests of each, as `RootFiles::folders`, a `stack::Folder` each. A folder that cannot be listed is kept as `unlisted`, and detection reports it as skipped.
- **Detection.** `stack::detect` runs the root's sources, then the same sources on each folder (`run_sources`, one loop for both). A folder's source is dropped when its kind is one the root, or the folder's container, detected, unless the folder holds that source's own lock or wrapper, the third column of `stack::SOURCES`: a member of the root's workspace has none. The tool chains in the home are never dropped by kind; a note already written is not written again (`fresh_toolchain_notes`). What a folder gives is rewritten by `in_folder`, which names every field of `Found`: the source becomes `backend/pyproject.toml (uv.lock)`, each line `cd backend && …` (`run_in`: braces around a command holding `;`, `||`, `&` or a line break, `./` before a folder starting with `-`, the folder quoted when it needs it), each `read from` comment ends `, in backend/`, each note starts ``in `backend/`: ``, and a skipped manifest is named `backend/package.json: …`.
- **Run caches.** `Detection::merged_run_caches` gives one entry per variable, its comment joining what each source read it from; `init::project_file` writes it. `Detection::run_caches` still gives one per source, which `init`'s report reads. A test pins that, over every source, a variable names one folder and a folder one variable, ignoring case as the loader does (`every_run_cache_detected_passes_the_names_check`). Past `agent_env::MAX_RUN_CACHES`, 16, the rest are written commented out under a note naming them, so `init` never writes a file its loader refuses (`run_caches_past_the_limit_are_left_commented_out`).
- **Notes reworded.** Five notes said "at the root", untrue in a folder: Gradle's ("beside the build file"), pdm's (`.pdm-python` "beside `pyproject.toml`"), .NET's two ("beside it", "side by side") and Elixir's ("beside `mix.exs`").
- **Tests.** `stack::tests`: `a_repository_of_folders_is_detected_one_folder_down` (Locary's shape), `the_roots_workspace_covers_its_members_unless_they_hold_their_own_lock` (Cargo, pnpm and uv, then Go and Makefile), `a_variable_two_folders_need_is_written_once`, `a_folders_lines_run_in_it_whatever_its_name_or_its_command`, `a_containers_folders_are_projects_unless_its_workspace_covers_them`, `the_folders_below_the_root_that_are_read`, `a_tool_chain_note_is_written_once_for_the_root_and_its_folders`. `init::tests`: `the_folders_below_the_root_are_read_as_the_root_is`, `a_repository_of_folders_is_written_once_per_variable_and_loads`, `run_caches_past_the_limit_are_left_commented_out`.
- **Decided in the ticket's alignment** (2026-11-24, from the ticket's own wording): the root covers its workspace and a folder with its own lock or wrapper counts; the folders of `apps/` and `services/` are read too.

## Live check R1, macOS (2026-11-24)

Script: [`owl-630.sh`](../live-checks/owl-630.sh): per fixture, a repository served on a local bare remote, `owlshift init --tracker markdown --skip-secrets` of this branch, its `owlshift.toml` committed unedited, then `owlshift gate`; for `mono`, once per `run_caches` line, that line alone removed. Owlshift's folders and git's global configuration are moved into a scratch folder.

macOS 26.6.2 (25G83), Apple silicon, `sandbox-exec`; node 25.9.0, pnpm 10.33.2 and uv 0.11.7 (Homebrew), Python 3.15.2. The network was fast that day; every package came from its public registry.

The `mono` fixture also got a note naming pyenv, this machine's pyenv living in the home; uv used Homebrew's Python and the gate passed without it.

It decides: a folder's lines pass confined as written, `cd` included; the variables the fixture's tools use fail the gate when removed, in a folder as at the root; one `PNPM_HOME` serves two folders, the second install reusing what the first fetched; a workspace's members are left to its root, whose lines pass.

## Live check R2, Linux (2026-11-24)

Script: [`owl-630-linux.sh`](../live-checks/owl-630-linux.sh): the same fixtures in Docker, Ubuntu 24.04.5 aarch64, bubblewrap 0.9.0, uid 1001, with a Linux build of this branch; node 24.22.3, pnpm 10.33.2, uv 0.11.7, Python 3.12.3.

All three fixtures green as written, the same `[stack]` as on macOS but for the pyenv note, none being installed: `mono` in 1 s, `shared` with `web/`'s install "reused 3, downloaded 0" and one store `pnpm/store/v10`, `workspace` with both members' tests. The removed-variable runs were not made: on Linux the private home lets an install with a variable left out succeed into a folder lost with the command ([OWL-617](OWL-617.md), [OWL-624](OWL-624.md)), so they cannot fail there. Linux shows "passes with"; "fails without" rests on macOS, as OWL-624's rule allows.
