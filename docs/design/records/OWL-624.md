# OWL-624 · Detect as many stacks as can be verified in owlshift init, run caches included

Settles: [runtime and operations](../runtime-and-operations.md), "Stack detection (P9)", "More stacks (OWL-624)"; [architecture](../architecture.md) section 8, "Caches a run may write", "Tool chains". This is the ticket's first slice: Go, poetry, pip, bundler and Gradle. The other ecosystems of the ticket, monorepos and the tool-chain notes are left to later tickets.

## As built (2026-11-22)

- **Detection.** `owlshift_core::stack::detect` walks a fixed list of sources, each a function of `RootFiles`: `cargo`, `go`, `package_json`, `python`, `ruby`, `gradle`, `makefile`. `MANIFESTS` is unchanged: the new sources read file names only, so `init::read_root_files` did not change. A skipped source is reported under the one manifest it reads (`manifest`).
- **Go** (`go.mod`): setup `go mod download`; gate `! gofmt -l . | grep .`, `go vet ./...`, `go test ./...`; `run_caches.GOMODCACHE = "go-mod"` and `GOCACHE = "go-build"`; a note that Go keeps its modules read-only, so the folder is made writable before it is deleted (`owlshift doctor` says deleting the tree empties it).
- **Python** (`python`): the tools of `pyproject.toml` as before, the manager from the first file found among `uv.lock`, `poetry.lock`, `pdm.lock` (each beside `pyproject.toml`) and `requirements.txt`. uv and poetry give their setup and run caches with no tool configured, with a note that no gate was written; for uv this is a change, since a `uv.lock` without a known tool gave nothing before. poetry: setup `poetry install`, `poetry run` before each tool, `run_caches.POETRY_CACHE_DIR = "poetry"`. pip, only with a tool to run (a root `requirements.txt` may serve a documentation build): setup `python3 -m venv .venv && echo '*' > .venv/.gitignore` (`PIP_VENV`), then `.venv/bin/pip install -r requirements.txt`, with `-r requirements-dev.txt` when that file is there; `.venv/bin/` before each tool; no run cache, and a note naming `PIP_CACHE_DIR` (R1). Without a tool, a note gives these lines. pdm keeps its note.
- **Ruby** (`Gemfile`): with `Gemfile.lock`, setup `bundle install` (bundler's plain install: a setup that rewrote the lock fails the gate, which lets it change ignored files only, and bundler 1.17 given `BUNDLE_FROZEN` writes that setting into `.bundle/config`, R1) and `run_caches.BUNDLE_PATH = "bundle"`; with `.rspec`, gate `bundle exec rspec`. Without the lock, no setup and no run cache; without `.rspec`, no gate; a note says each.
- **Gradle** (`gradlew` beside a `build.gradle(.kts)` or `settings.gradle(.kts)`): gate `./gradlew check --no-daemon`, `run_caches.GRADLE_USER_HOME = "gradle"`. A build without the wrapper gets a note only.
- **`init`** writes a source's notes above what it gives, and above nothing when it gives no line (a `Gemfile` with neither lock nor `.rspec`, a Gradle build without its wrapper), never above a gate `--gate` replaced (`init::project_file`).
- **The rule for a variable** (the approval's guardrail): a run cache is written only when the real `owlshift gate`, confined, passed with it and failed with that variable alone removed, on macOS at least, and passed on Linux whenever the rig could run; otherwise a note names it. An ecosystem whose gate never passed confined would be a note alone. Pinned by `stack::tests::pip_installs_into_a_self_ignoring_venv_and_only_names_its_cache`; every variable written passes `agent_env::check_run_caches` (`every_run_cache_detected_passes_the_names_check`).
- **Decided with the slice.** Tool chains, written into architecture section 8. Monorepos: detection reads the root; a stack one folder down is a later ticket.

The network of the check ran at 15 to 50 kB/s, its downloads stalling now and then, against 30 minutes for a gate and a third of it for its setup. Two sources were therefore served on the loopback by the script, as OWL-617's bench serves its registry: the fixture's gems, fetched once by name from rubygems.org and indexed with `gem generate_index` (bundler 1.17's `bundle lock` against rubygems.org had stalled 24 minutes on its 25 MB index), and the Gradle distribution, the machine's own zipped as gradle.org ships it (130 MB). Bundler and the wrapper still download them over HTTP into the run caches; the Go modules, the Maven artifacts and the Python packages come from their public registries. The Python fixtures were run without ruff (`PY_TOOLS=pytest`) once its wheel had stalled twice past the deadline, unconfined `curl` stalling on the same files: the `ruff check .` line is OWL-539's rule, run through the same `poetry run` and `.venv/bin/`. The fixtures' lock files were made unconfined, their caches in the scratch folder; one `bundle lock` of a first run, before that was so, wrote rubygems.org's index cache into the person's `~/.bundle/cache/compact_index`.

It decides: Go, poetry, pip, bundler and Gradle are kept, each with the lines above; every variable written passed with it set and failed with it alone removed. On this machine poetry needs `.pyenv` declared, as `owlshift gate` proposes; that is the machine's pyenv, not the project's, so `init` writes no cache for it.

## Not checked

- Linux, above; and on macOS, a modern bundler (2.x), whose lock naming a newer bundler than the machine's makes it install that bundler first, outside `BUNDLE_PATH` (the rig's `bundler-pinned` case, written and not run, decides whether `GEM_HOME` is needed).
- Two confined runs writing one of the new folders at once (OWL-617's R2 covered cargo, pnpm, npm and uv).
- A `Gemfile.lock` made on macOS whose `PLATFORMS` lacks the Linux runner's: bundler adds the platform to the lock or refuses it, and either fails the gate, as it would the project's own Linux CI.
- A poetry project in package mode without its package folder, which `poetry install` refuses, as it would unconfined.
- A Python project that does not ignore `__pycache__`, or a Gradle one that does not ignore `.gradle/` and `build/`: the gate fails naming the files, as for any tool that writes beside the sources. The fixtures ignore them, as projects do.
