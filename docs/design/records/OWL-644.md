# OWL-644 · Run the macOS check of NUGET_SCRATCH for concurrent .NET restores

Settles: [runtime and operations](../runtime-and-operations.md), "More stacks (OWL-624, OWL-627, OWL-628, OWL-629)": the macOS single run and pairs that the sentence on `NUGET_SCRATCH` named pending, and the first item of [OWL-641](OWL-641.md)'s "Pending", whose "macOS is described as checked nowhere" this supersedes. OWL-641's record is not edited.

## Live check R1, macOS (2026-11-23)

macOS 26.6.2 (25G83) arm64, .NET SDK 11.0.100 (Homebrew), `owlshift` 0.2.0 as a debug build of `main` at 021c92d0. Rig: [`owl-627.sh`](../live-checks/owl-627.sh) `dotnet` with `CONCURRENT=1`, unchanged, started 20 times one after the other from 13:07Z to 14:50Z, alternating `STACK_EDIT='/^run_caches.NUGET_SCRATCH = /d'` (the half without) and no edit (the half with), the commands OWL-641's "Pending" names. Each start makes the fixture, runs single gates confined (as written, then each run cache alone removed), then one pair on an emptied run cache tree, then a third gate alone. The single gate with the variable set is the "as written" gate of the half with; the half without has no "`NUGET_SCRATCH` alone removed" gate, since its edit already removed the line.

| `[stack]` | Pairs with a red gate | Red gates | Third gate alone | Single gate as written | One gate, `NUGET_SCRATCH` alone removed |
| --- | --- | --- | --- | --- | --- |
| `NUGET_SCRATCH` removed | 7 of 10 | 11 of 20, at `dotnet restore` but one | green 10 of 10 | green 10 of 10 | |
| as `init` writes it | 0 of 10 | 0 of 20 | green 10 of 10 | green 10 of 10 | green 10 of 10 |

The red restores failed in the shared packages folder as on Linux: `Could not find file '<run cache>/dotnet/.nuget/packages/<package>/<version>/<random name>'` (5), `Directory not empty` (3), the package `microsoft.codecoverage` six times and `microsoft.testplatform.objectmodel` twice; and `The process cannot access the file` once on NuGet's `http-cache` and once on `<run cache>/dotnet/.nuget/NuGet/NuGet.Config`, which both restores of a pair create on an empty run cache. None of these was seen with the variable set. In the pair of start 6 both gates then ended on a signal, `System.NullReferenceException` in `System.Net.Security.SafeDeleteNwContext` (.NET's Network.framework TLS): one during `dotnet restore` after the `http-cache` error, the other during `dotnet test` after a restore that succeeded. That second gate is not the lock's doing; counted without it, 6 of 9 pairs are red, still most. The exception was seen nowhere else in the 110 gates run. NuGet left `nuget-scratch` empty (0 kB) after each start of the half with, where Linux left 8 kB.

**Load.** Sibling agents built and tested on the same Mac throughout: the one-minute load average at each start's beginning ranged from 4 to 160 (Apple silicon, 18 cores), above 60 for 12 of the 20 starts. The three green pairs of the half without came last (starts 8 to 10, 14:26Z to 14:47Z, as the load fell from 103 to 11), so how often the race is lost on macOS may depend on load. The half with was as loaded and stayed green.

It decides: macOS agrees with Linux under the rule's clause for a variable that only orders runs (most pairs red without, every pair green with, at least ten each way, a single gate green with it set), so `init` keeps `NUGET_SCRATCH`. Its note now says "checked on Linux and macOS". [`recipes.md`](../../recipes.md) and the "More stacks" sentence say so too.
