# OWL-652 · Keep the cause line when summarizing a failed git command

Settles: the summary of a failed git command in warnings and events; no design document states it.

## As built (2026-11-26)

`owlshift_adapters::git_stderr::summary` is the one summary of git's standard error. It drops git's fixed closing lines, keeps the last three lines that remain, joins them with ` / `, removes `user:password@` from every URL, then cuts at 400 characters. Redaction comes before the cut, so a cut inside a credentialed URL leaves no token behind. Its callers: the executor's `Git::run` errors (`executor/git.rs`, which had no redaction before), the push verdicts (`forge/push.rs`, whose `redact_userinfo` moved with it) and the two claims fetches (`claims.rs`, which kept only git's last line, "and the repository exists."). It lives in the adapters crate because the runner already depends on it and `owlshift-core` is not a dependency of it. The summary applies to every runner git command, local ones too: an empty stderr now reads `no error output`, and a detail longer than 400 characters is cut.

## Live check G1 (2026-11-26)

Apple Git 2.54.0, `LC_ALL=C git ls-remote /nonexistent/owl652`, which exits 128 with:

```
fatal: '/nonexistent/owl652' does not appear to be a git repository
fatal: Could not read from remote repository.

Please make sure you have the correct access rights
and the repository exists.
```

Decides the three fixed lines the filter drops. Every runner git command runs with `LC_ALL=C`, so the match holds; a localized git would fall back to the last three lines, as before. `GitError`'s `Display` prints the command's arguments unredacted; they name the remote by name today, not by URL.
