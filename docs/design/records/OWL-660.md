## As built (2026-11-26)

- **The base lock and record.** `ProjectDirs::base_lock` (`<project>/base/lock`, taken as a ticket's lock is) and `base_lock_held` (one try). `ticket_run::write_base_run` and `read_base_run` (`BaseRun`, `base/run.json`, `schemas/base-run.schema.json`): a generation raised past the one read and the clock's milliseconds, the base branch's commit, the worktree's entry. It is written after the worktree is made, before it is removed, and at the end whatever happened. A record that does not read reads as none.
- **Siblings.** `ticket_run::Siblings` reads the base check as one more sibling (`Siblings::base_check`). `Siblings::for_base_check` gives the base check's own check every other ticket and not itself.
- **The executor.** `Executor::run_gate` is now `make_gate_worktree` then `gate_in`. `gate_in` takes the siblings and checks among them. `Executor::discard_own_worktree` (`worktree::Forget::OwnEntries`) removes the entries whose `gitdir` names the worktree (`ticket_run::entries_of`), by name, never by `git worktree prune`.
- **The check.** `GateOnce::run` sends `owlshift gate` to `run_alone`, which is unchanged, and a base check to `run_beside`:
  1. A first section: quarantine, fetch, plan, and the verdict kept at this head, with no base lock.
  2. The base lock.
  3. A second section: quarantine again, leftovers, obligation `<ticket>-<stamp>-base`, worktree, record.
  4. The gate outside the lock.
  5. The obligation removed once the check passes.
  6. A last section, waited for up to five times the lock's bound: record, worktree removed, quarantine looked at again, verdict kept.
  7. The record's last write before the base lock goes.

  `ticket_run::ticket_in_flight_except` became `ticket_in_flight`: only `owlshift gate` asks it now.
- **Watch.** The priority is gone: `base_due_holds`, `BASE_DUE_AT_MOST`, `base_due_ran`, `base_due_given_up`, the give-up in `run_passes`, `dark_wake_held`, and the hold of base-held tickets while another's check was due. `Memory::base_due` is now the set of tickets whose check waits. `base_released` lifts each one's retry hold once `base_lock_held` is false. `base::pending_tickets` gives every waiting ticket to a watch started again. `refresh_base_check` is no longer told; `merge.rs` still phrases the ones kept in the log.
- **Texts.** A pending hold now reads "is checked once the base check running now ends" (`Stop::BaseHeld`, `why`).
- **Tests.**
  - `ticket_run::tests::the_base_check_is_one_more_sibling`.
  - `gate_once::tests::a_base_check_runs_beside_the_steps_and_a_breach_is_caught_on_both_sides`: the project's lock is free during the gate; the sibling's moves are not a breach; a planted tag and the checking ticket's own branch are caught by the base check, the tag by the sibling.
  - `gate_once::tests::a_base_check_whose_last_section_is_refused_keeps_nothing_and_leaves_its_worktree`.
  - `base_scenarios::a_pending_check_holds_no_other_step`.
  - `child_steps::an_answered_ticket_goes_on_while_another_tickets_base_check_runs`: real children, a real check kept running.
  - The base scenarios that used a sibling's ticket lock to make a check wait now hold the base lock. The busy drain's OWL-431 bound is now pinned with a step in flight that the check runs beside.

## Upgrade

The daemon's upgrade stops every watch's steps before the new binary runs (P8). So no step of an older binary, which knows nothing of the base lock and record, runs beside a check of the new one. A `base/worktree` left by an older check is found by its entry's `gitdir` and removed.
