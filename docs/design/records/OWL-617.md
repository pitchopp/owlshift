# OWL-617 · Give a project's runs caches they may write

Settles: [architecture](../architecture.md) section 8, "Caches a run may write"; [build plan](../build-plan.md), "P5 · Quality pipeline", part W.

## As built (2026-11-21)

- **The key.** `stack.run_caches`, a table from a variable to a folder's name (`Stack::run_caches`). Checked at load by `owlshift_core::agent_env::check_run_caches`, then by `Stack::check_run_caches` against `stack.gate_env`. Built otherwise than designed, and written into section 8 by this change: beyond `stack.gate_env`'s refusals, a name Owlshift passes to every agent itself (`INHERITED`, `LOCALE_CATEGORIES`, `PROXY_VARIABLES`, in any letter case) and a name `stack.gate_env` declares are refused, since `PATH`, `HOME` or `TMPDIR` set to a folder would change the confinement and one variable cannot take two values. A name must be a variable name, a folder one name of ASCII letters, digits, `.`, `_` and `-` not starting with `.` (at most 64 bytes), names and folders unique in any letter case, at most 16 entries. No allow-list of the operator's, as designed: a run-written `PYTHONPATH` is the risk class of a crate a run leaves in `CARGO_HOME`, which section 8 accepts.
- **The tree.** `<cache directory>/owlshift/github.com/<owner>/<repo>/<folder>` (`owlshift_platform::paths::cache_dir`, `run_caches::tree`), laid out by `project::repo_folder`, which `ProjectDirs::new` now shares. `OWLSHIFT_CACHE_DIR` replaces `<cache directory>/owlshift` by `OWLSHIFT_DATA_DIR`'s rule, the way out for a cache directory whose path holds a space. `run_caches::prepare` makes the folders and refuses, naming the path: no cache directory, a tree whose path holds a space, a place taken by something that is not a folder. `do_cmd::agent_env` builds the agent environment for `do`, `continue`, watch's step children and `gate` alike. Since the sandbox opens a folder by its real path, read and written, `run_caches::make` walks every part from the cache directory down to each folder with `symlink_metadata`, before and after making it, and refuses one that is a symbolic link or not a folder, naming it, then checks that the folder's real path stays under the cache directory's; the cache directory itself, the operator's, may be a link. Found by a cross-review of the pull request: a run cannot write the tree's folders, but the rule holds by a check. Pinned by `run_caches::tests::a_planted_link_in_the_tree_is_refused`.
- **The sandbox.** `AgentEnv::with_run_caches`: each folder is in the policy's writable list, or its readable one under the read-only profile (design, review, verify and arbiter runs), and each variable is set by `AgentEnv::environment` on the confined command alone, never in `AgentEnv::vars`, which `Git::as_agent` hands to the runner's own git outside the sandbox. Every confined spawn makes and checks the folders again (`AgentEnv::sandboxed`, as for the web UI's token folder; a refusal is `SandboxError::Refused`), so a tree deleted during a long watch comes back empty instead of being skipped by bwrap's `--bind-try`, and a link planted since the command began is never opened.
- **`owlshift init`** writes, each under its `# read from` line: `CARGO_HOME = "cargo"` for a `Cargo.toml`; `npm_config_store_dir = "pnpm-store"` with the setup `pnpm install --frozen-lockfile` for pnpm 10; `npm_config_cache = "npm"` with `npm ci` for npm; `UV_CACHE_DIR = "uv"` and `UV_PYTHON_INSTALL_DIR = "uv-python"` for `uv.lock` (R1: uv needs both on macOS). These replace OWL-593's npm and OWL-598's pnpm recipes, which read the person's cache read-only, and need no `allow_caches`. `owlshift gate`'s advice for a refused home folder (`cache_offer`) names `stack.run_caches`.
- **`owlshift doctor`** has a `run caches` line in the project section: the tree's path and size, and that deleting it empties it; a failure when no run could make it (`System::run_cache_dir`). The size walk stops at 200,000 entries and says "at least".
- **The Build's prompt** (`roles/build.md`, "Building") says its installs go to the folders the run caches' variables name, in one sentence: the prompt's 120-line budget and its rule that it names no key of the project file keep it there.
- **The bench.** `confined_setup.rs`, `a_setup_installs_a_missing_package_into_its_run_cache`: confined, the setup installs the fixture's package from a registry served on the loopback into a run cache, the bench's home holding no store; another worktree's setup then installs it `--offline` from that cache.
- **Noted.** On macOS the folders above an opened one are listable (`above_opened`), so a run can list the names in `~/Library/Caches` and the other repositories' trees of the same owner, as it already lists `~/Library/Application Support` above its worktree. A read-only run's cargo cannot take its package-cache lock in a read-only `CARGO_HOME`, as with `~/.cargo` before; not checked. This repository's own `owlshift.toml` is left as it is: using the key needs `requires` past the Owlshift 0.2.0 the maintainer's runner has.
