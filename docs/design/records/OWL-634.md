# OWL-634 · Give the rebase verdict to a Watch repair run that stops blocked

Settles: [architecture](../architecture.md) section 4, "A `blocked` through the resolver". Follows [OWL-620](OWL-620.md), whose "Built otherwise than designed" left `rebase` closed at Watch.

## As built (2026-11-22)

- **Where it is open.** A fix, correction or person's results run at Watch (`RepairRun.rebase`, Owlshift's last push). `rebase` is open when that push does not hold the base's head as this command fetched it, and `RebaseDue` would not park at the repairs' bound. A delivery git cannot read is not rebased. It stays closed for Watch's rebase run itself and for a resolution's last fix.
- **The bound.** Once per ticket and stage, as at Build: `unblocks_at(Stage::Watch)` holds the verdict, and a later `blocked` at Watch after a `retry` or a `rebase` parks.
- **The act.**
  - `repair_runs` ends with `RepairEnd::Rebase` once the verdict's DECISION is kept.
  - `repair_or_rebase` then calls `repair_rebase` with the new cause `RebaseCause::Unblocked` (`"unblocked"` in `rebase_run` events). The cause is a refresh: watch starts these three runs only on a read with no conflict.
  - The rebase run starts from Owlshift's last push, so the blocked run's work is dropped. A `blocked` run has no gated commit.
  - Its push ends the repair and counts one repair and no fix pass. The blocked run does not run again in that pass. Watch's next pass decides on the rebased head: a red read gets a fresh fix run on that head's logs, and an unfollowed correction or a due person's results run runs there.
- **Unchanged.**
  - The rebase brief is the delivered pull request's, with `refresh`. `RebaseBrief.unblocked` stays a Build's that is not delivered, and the brief format does not change.
  - The reason is in the DECISION comment and the `rebase_run` event's `cause`.
- **Tests.**
  - The core's rule table, Watch rows.
  - The cause's name and refresh.
  - On the bench, `unblock_scenarios.rs`: a fix run blocked on its base is rebased and its push lands. The existing scenario, with the base not moved, keeps `retry` and `park`.

## Built otherwise than designed

- **Open on a moved base, not on a base that is the obstacle.** The runner can only tell that the base moved. Whether the stop is the base's is the resolver's reading, and `roles/resolver.md` asks for `rebase` only when the run's stop names what the base gained.
